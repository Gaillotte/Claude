# Divergence register

> **2026-11-14: the Python engine is a thin port.** The owner chose a Python engine that reproduces the bash engine
> exactly and calls the same tools (`docs/python_port_thin_plan.md`). Every `fix-in-python` decision below that is not
> also fixed in bash is therefore **not implemented**: the Python engine copies bash, and the goldens (recorded from
> bash) are the only target. The modular engine these entries were written for is parked at commit `796d5a9`.

Every place where the Python engine (`scan_pipeline.py`) is allowed to behave differently from the bash engine
(`scan_pipeline.sh`, the oracle until cut-over). `docs/engine_contract.md` says what both engines must do and, in its
section 11, which bash behaviours look accidental; this file records, one entry per behaviour, what the Python
engine does about each and who decided.

Without an entry, a difference between the two engines is a bug in the Python engine. `conformance.py diff` is
the test that finds them; a difference it reports must either be fixed or be given an entry here.

## Rules for adding an entry

1. **One behaviour per entry.** Ids are `D-nnn`, ascending, never reused, never deleted. A resolved entry is
   closed, not removed.
2. **Evidence.** The bash cell names the contract item (`A1`, section 8.3) and the experiment that reproduces it
   (`E1`, Appendix A of the contract), or a command line that does. "I think bash does X" is not an entry.
3. **The Python cell must be testable.** Write what the Python engine does precisely enough that a fixture and an
   assertion can pin it, and name the golden case or normaliser rule that has to change, if any. A new case in
   `tests/conformance/conformance.py` is the preferred pin.
4. **Decision** is one of:
   `copy` (Python reproduces bash exactly, for compatibility; the entry exists so nobody "fixes" it by accident),
   `fix-in-python` (Python deliberately differs, bash keeps the behaviour until it is retired),
   `fix-in-both` (the defect is fixed in bash too, in a separate change, and the golden files are regenerated),
   `drop` (the code path is dead and is not ported),
   `needs-decision` (the lead has to choose; the Python engine copies bash meanwhile).
5. **Status** is `proposed` (written, not reviewed), `accepted` (the lead agreed), `implemented` (Python does it
   and a named test pins it), or `closed` (bash was fixed or retired, so there is nothing left to differ).
6. **Changes to what a report contains need sign-off before `accepted`**: any difference in a recorded message,
   a `file_results` status, a `coverage` state, a finding record or the verdict. A difference confined to stderr,
   timing or ordering does not.
7. **Not an entry:** the things listed in section 10 of the contract (ordering, JSON layout, timing, console
   wording, tool stderr, hash order). They are allowed everywhere.
8. While the feature freeze lasts, a bash fix (`fix-in-both`) changes `scan_pipeline.sh`, so it is scheduled by the
   lead and not done as a side effect of the port.
